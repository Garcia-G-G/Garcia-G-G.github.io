How it works

  1. One tracking snippet per sub-account. It stores gclid, gbraid, wbraid, fbclid, ttclid and the UTMs in a first-party cookie, and writes them into custom fields on the contact. The app creates those fields for you on install.
  2. The ID rides along. Form, booked call, opportunity — the click ID stays attached to the person, not to the session.
  3. The close gets a real timestamp. GoHighLevel's API has no wonDate, so Won Date listens for the status change and seals its own. From then on, revenue lands on the day it was actually won.
  4. The conversion goes back out. Offline conversion upload to Google Ads, Conversions API to Meta, Events API to TikTok — so the platforms optimise toward closed deals instead of toward chat volume.
  5. One export per sub-account. Cost per booked appointment and cost per closed deal, in a table you can put in front of the client without apologising for it.

Two limits I'd rather tell you now

Meta only accepts events up to seven days old. If your client's sales cycle is longer than a week, Meta gets the conversion but not the true close date. Google and TikTok don't have that limit. Anyone who tells you otherwise hasn't read the docs.

There's no backfill. Deals already won before you install can't be reconstructed — GoHighLevel never stored the close date to begin with. Attribution starts the day the snippet goes in.
